# 自動テスト

サイトをブラウザで自動的に開いて、「壊れていないか」を37項目チェックします。
作品を追加したとき・見た目や文章を直したときに `npm test` を1回動かすと、
自分で全部のページを見て回らなくても、うっかりミスに気づけます。

## 最初の1回だけやること

ターミナル（VS Code なら「ターミナル → 新しいターミナル」）で、`tests` フォルダに移動して2つ実行します。

```bash
cd tests
npm install      # テスト用の部品（Playwright）を tests/node_modules に入れる
npm run setup    # テスト用のブラウザ（Chromium）をダウンロードする（数百MB・数分）
```

## テストを動かす

```bash
npm test                 # 全部（2分ほど）
npm test -- 作品         # 名前に「作品」を含むテストだけ
npm test -- 英語 はみ出さ # 「英語」か「はみ出さ」を含むテストだけ
npm test -- --headed     # ブラウザの画面を出して、動いている様子を見る
```

`portfolio` フォルダ（1つ上）で `npm test` と打っても動きます。

## 結果の見かた

```
■ 1. 作品データとファイル
  ✔ data/works.js が正しく読み込める 0.0秒
  ✘ 作品の画像・プレイ動画のファイルがある 0.0秒
      → ファイルが見つかりません（名前や場所、大文字小文字を確認）
      ・1番目「新しい作品」 の画像: images/index/otherworks/NewGame.webp
...
失敗 1 件 ／ 合格 36 件 ／ 全 37 件
```

- `✔`（緑）… 合格
- `✘`（赤）… 失敗。すぐ下の `→` に理由と、問題の場所が出る
- 失敗したときの画面は `tests/results/` に画像で保存される（GitHub には上がらない）
- 最後に「すべて合格です！」と出れば OK

## 失敗したときは

1. `→` の理由を読む。多くは「どのファイルの何番目の何がおかしいか」まで書いてある
2. 直して、そのテストだけもう一度動かす（`npm test -- テスト名の一部`）
3. 理由がよくわからないときは `tests/results/` の画像を見る、または `--headed` で動きを見る

「わざと変えた」のに失敗する場合（たとえば日本語のまま見せたい部分を作った）は、テストのほうを直します。
英語にしない部分は、HTML に `data-no-translate` を付けると英語チェックの対象外になります。

## ファイル

| ファイル | 中身 |
|---|---|
| `run.mjs` | テストを動かす本体。小さなサーバーを立ててサイトを配り、ブラウザを起動して `cases/` のテストを順に実行する |
| `cases/1-data.mjs` | 作品データ・ファイル・リンク切れ（ブラウザを使わないので一瞬で終わる） |
| `cases/2-page.mjs` | エラーなく開けるか・はみ出し・英語表示 |
| `cases/3-a11y.mjs` | だれでも使えるか（alt・ボタンの名前・見出し・ボタンの大きさなど） |
| `cases/4-controls.mjs` | 設定・絞り込み・作品ビューアー・効果音・ゲームパッド・いいね |

## テストを増やすとき

`cases/` のファイルの `tests` の中に、次の形で1つ書き足します。

```js
{
    name: "テストの名前（何を確かめるか）",
    async run({ open, expect }) {
        const { page } = await open("/");                       // ページを開く（スマホなら open("/", { phone: true })）
        const text = await page.locator("h1").textContent();     // ページから情報を取る
        expect(text.includes("長屋"), "h1 に名前がありません"); // 成り立たなければ、この文で失敗にする
    },
},
```

`page` は Playwright のページです。できることは https://playwright.dev/docs/api/class-page を参照。

## 知っておくとよいこと

- テストは外のサイト（アクセス解析・いいね・Google Fonts など）に通信しません。
  本物のアクセス数やいいねは増えないので、何回動かしても大丈夫です
- GitHub の自動更新（note の記事取得）とは別の場所（`tests/package.json`）で部品を管理しているので、そちらには影響しません
